# 国内の薄い板への両側指値 (マーケットメイク) シャドーモード — TRA-65

bitbank の板が薄いアルト 5 銘柄に指値を両側に出す型が成立するかを、**一切発注せずに**測る。

- 叩くのは 3 つだけ: `GET public.bitbank.cc/{pair}/depth` / `GET .../transactions` /
  `POST api.hyperliquid.xyz/info {"type":"l2Book"}`。**どれも公開・読み取り専用。鍵も口座も無い。**
- 注文系 API には触らない。`deploy=["live"]` も `wrangler.toml` の `live` も変更しない。

## なぜこの型か

売上が「取れた出来高 × 半スプレッド ＋ メイカー手数料」で決まり、**資金量では決まらない**。
bitbank のアルト全銘柄はメイカー **−0.02%** (約定すると受け取れる) / テイカー 0.12%。
一方、国内で空売りできる 5 銘柄 (btc/xrp/eth/sol/doge) はスプレッドが 0.001% 以下なので、
国内だけでは完結しない → **在庫のヘッジは Hyperliquid perp に出す** → perp がある銘柄だけが候補。

## 事前宣言 (`tbf/jpmaker/declared.py`。結果を見て動かさない)

| 項目 | 値 |
|---|---|
| 対象 | `render_jpy` `gala_jpy` `imx_jpy` `dot_jpy` `op_jpy` |
| サイズ | 1 注文 ¥50,000 / ¥200,000 |
| 純収益 | `Σ(約定金額 × (半スプレッド + 0.02%)) − 逆選択損(60s) − (スリッページ + 0.045%×2)` |
| 年率の分母 | 投下資本 = 在庫上限 (1 注文 × 2 側 × 銘柄数) × 1.5 (ヘッジ証拠金 50%) と **実測秒数** |
| 床 / 合格 | 年 5.12% / 年 15.36% (床の 3 倍) |
| 安定性 | 窓ごとの年率で **床を割る窓が半分を超えたら不合格** |
| 窓 | 1 日 / 3 日、境界は UTC 0 時。端数窓は実経過時間で年率化 |
| 約定率 | 保守 (置いた瞬間の最良数量が全部前に居た) / 楽観 (自分が先頭) の **2 推定**。判定は保守側 |
| 逆選択 | 10s / 60s / 300s / 1800s を測り、**式に入れるのは 60s だけ** |
| 逆選択の基準 | 式に入るのは `Σ(1 件ずつ)` = 平均の基準 (`ADVERSE_BASIS_FOR_NET="sum"`)。判定はこれだけ |

2026-11-14 のリーダー指示で**報告の形に 1 項目追加**した (線は変えていない): 逆選択は
約定 1 件あたりの **中央値と平均の両方**を出し (レポート 3-b)、**どちらを使うと合否が反転するか**
を明記する (3-c)。裾の長い量なので 1 件の外れ値で平均が動く — 社内の実例として Lido の
`apr/sma` は日次 7 点のうち 1 点 (15.077%) に押し上げられて 4.242% を返すが実体は中位 2.27%。
**合否は常に平均 (sum) 基準で報告し、中央値は感度として並べるだけ。**

設定ファイル (`jp_maker.toml`) で銘柄・サイズ・ポーリング間隔を宣言グリッドから外すと
`load_config` が例外で落ちる。「成績の良い銘柄だけ残す」操作を設定からできないようにしている。

## 測り方の注意 (過去に踏んだ穴)

- **穴をゼロ埋めしない。** 標本が 3 秒以上途切れた区間は「未測定」として、約定・逆選択・
  年率の分母すべてから外し、レポートに全件 (60 秒以上は 1 件ずつ) 列挙する。
- **古い値段をそのまま使わない。** 逆選択の中値は地平ごとの許容 (`max(3s, 地平×10%)`) の外なら
  未測定扱い。古い値段で評価すると「値段が動かなかった」ことになる (TRA-62 で踏んだ穴)。
- **3 分しか測っていない区間を「1 日窓」として判定しない。** 窓幅が宣言幅の 50% 未満、または
  カバレッジが 50% 未満の窓は判定から外す (除外した窓も行として出す)。
- **テープの `side` の意味を検算する。** `side` をテイカーの向きと解釈しているので、
  `side=sell` の約定値段が中値より下に寄っていることをレポートで必ず確認する。逆なら
  買い側と売り側の約定率が入れ替わる。
- **ヘッジまでの時間差は下限。** 口座が無いので注文の往復は測れない。約定検知 1 秒 (板の
  取得間隔) + `l2Book` 往復の実測 p50 を下限として使う。実運用はこれより悪くなる。

## 運用

```bash
# 7 日連続で記録する (ログは logs/tra65-jpmaker.log)
setsid nohup env PYTHONPATH=. python -m tbf.jpmaker run \
  --config jp_maker.toml --db data/jp_maker.sqlite >> logs/tra65-jpmaker.log 2>&1 &

python -m tbf.jpmaker report --days 7 --out reports/tra65.md
```

叩く頻度は `public.bitbank.cc` が `cache-control: max-age=1` の静的キャッシュなので 1 秒が下限
(それより速く叩いても中身は同じ)。`transactions` は最新 60 件しか返らないので 60 秒間隔で取り、
全件が未知だった回は `tape_overflow` に印を残す (取りこぼしの疑いを推定で埋めない)。
Hyperliquid の `l2Book` は weight 2 なので 5 銘柄 × 12 回/分 = 120 weight/分 (予算 1200)。
